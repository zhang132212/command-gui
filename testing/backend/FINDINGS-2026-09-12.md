# 2026-09-12 后端回归发现

以下记录首次测试时发现的缺陷。后续已按用户要求修复产品后端，原失败断言保留作为回归验收条件。

|问题|失败用例|定位与影响|
|---|---|---|
|无权限玩家可占用编辑锁|`unprivileged guest cannot acquire edit lock`|`MachineManager.editSession` 打开锁前未检查编辑权限。普通玩家可阻止正常编辑和机器操作。|
|占位符在权限预检查前未展开|`toggle starts real spawn then on timeline`、`multi-mode start order and interval`、`single-select replacement stops before starting`|机器及模式路径将 `player {bot} spawn ...` 原样交给 Brigadier 预检查，OP 也收到权限不足；固定假人名称的开机、多模式对照用例通过。|
|召唤超时后运行状态不释放|`spawn await timeout does not fake completion`|`MachineScheduler.tick` 的超时分支设置 `finished`，但未清除 `awaitBot`；后续持续进入等待分支，不能到达移除运行项的分支。运行超过 1000 tick，仍反复报告 900 tick 超时。|
|权限预检查漏判受限根命令|`mode cooldown fallback and permission capture`|`checkCommandPermission` 只判断解析异常集合。普通玩家无法执行的 `qarestricted` 根节点可得到空异常集合，被误判为允许。实际执行阶段拒绝用例通过，因此不能据此声称已经发生提权执行。|
|独立停止顺序配置未生效|`stop chain independent stop order`|`MachineModeChain.buildChains` 将 `stopFollowsStart` 直接作为 `orderedIds` 的 `forStops` 参数。关闭“停止跟随启动”时反而选择启动顺序；预期 b→a，实际 a→b。|

完整堆栈、逐项状态和依赖版本以最新一次运行的 `build/backend-tests/<运行编号>/report.md`、`report.json` 为准。以上不是预期失败白名单：未修复时脚本应返回非零退出码。

## 修复内容

- 编辑会话打开时检查 `canEdit`；失去权限的原锁主仍可关闭自己的会话。
- 预检查和调度执行共用命令展开方法，使用步骤指定的假人索引，替换 `{bot}` / `{player}` 并补齐 spawn 默认朝向。
- 预检查要求指令完整解析且存在可执行节点，拒绝受限根节点、未知命令、不完整命令和多余参数；预检查不执行指令。
- 召唤超时清除等待状态，让调度器回收运行项；模式超时同样反馈一次失败消息。
- 独立停止顺序使用 `stopModeOrder`，跟随启动时使用 `modeOrder`，间隔保持对应配置。

新增回归用例覆盖模式召唤超时、未知/不完整指令，以及开启“停止跟随启动”时的顺序和间隔。最终实测结果见下方验证记录。
